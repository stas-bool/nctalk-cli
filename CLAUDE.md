# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

`nctalk` — тонкий CLI-клиент над Nextcloud Talk (Spreed) поверх OCS-API на Go 1.21 (только stdlib). Потребитель — агент (через skill-обёртку) и человек в терминале. Бизнес-логику клиент не содержит — только примитивы (10 команд). Эталон контракта команд, exit-кодов и поведения — **спека** `docs/superpowers/specs/2026-07-17-nctalk-cli-design.md` (базовые 7 команд) и дельты `docs/superpowers/specs/2026-09-08-nctalk-chat-edit-design.md` (`chat edit`), `docs/superpowers/specs/2026-09-09-nctalk-rooms-participants-design.md` (`rooms participants`), `docs/superpowers/specs/2026-09-29-nctalk-threads-design.md` (`chat threads` + `--thread`/`--thread-title`) и `docs/superpowers/specs/2026-10-09-nctalk-chat-attach-design.md` (`chat send --attach`; читай при любой правке поведения).

## Сборка, тесты, запуск (CGO_ENABLED=0 обязательно)

На этой машине (macOS Tahoe 26.5 + Go 1.21.4) обычный `go test`/`go build` падает с `dyld: missing LC_UUID` — **всегда ставь `CGO_ENABLED=0`**.

```sh
CGO_ENABLED=0 go build ./...                       # сборка
CGO_ENABLED=0 go build -o nctalk ./cmd/nctalk       # бинарник
CGO_ENABLED=0 go vet ./...                         # линт
CGO_ENABLED=0 go test ./...                        # все unit-тесты (не integration)
CGO_ENABLED=0 go test ./internal/client -run TestName -v   # один тест
```

**Makefile**: `make build` / `make vet` / `make test` — обёртки под `CGO_ENABLED=0`; для базового `nctalk` достаточно и команд выше.

Запуск:
```sh
export NEXTCLOUD_URL=https://nc.example.org NEXTCLOUD_LOGIN=... NEXTCLOUD_PASS=...  # PASS — app-password, только env
./nctalk rooms list
```

Интеграционные тесты на боевом сервере — за build-тегом `integration` (не входят в `go test ./...`), требуют env-кредов; мутации (`SendMessage`/`EditMessage`/`Threads`/`SendFile`) — под флагом `NCTALK_INTEGRATION_SEND=1` + `NCTALK_INTEGRATION_ROOM`. Подробно: `docs/integration-run.md`.

## Архитектура

Четыре слоя, строго однонаправленные: **config → client → cli → render**. main.go только связывает их через тестируемую `run(args, stdout, stderr, stdin) int` (вся логика вне `os.Exit`, чтобы тестировать вывод в `*bytes.Buffer`).

- **`internal/config`** — читает env (`NEXTCLOUD_URL/LOGIN/PASS/TIMEOUT`), нормализует URL (трим trailing slash, схлопывание `//`, запрет userinfo в URL, схема http/https). Сообщения об ошибках содержат **только имена env-переменных, никогда значения**.
- **`internal/client`** — ядро `TalkClient`. Ничего не знает про CLI/вывод. Методы над OCS: `ListRooms/FindRooms/SearchRooms/GetChat/SendMessage/SendFile/EditMessage/GetReactions/GetParticipants/ListThreads/SearchMessages` (`SendFile` — OCS + WebDAV через `transport.DoDAV`). Зависит от интерфейса `httpDoer` → мокируется в тестах. Единый транспорт `doOCS(ctx, method, path, query url.Values, body, mutate, out) (http.Header, error)` собирает URL, Basic-auth + заголовки `OCS-APIRequest: true`/`Accept: application/json`, разворачивает конверт `ocs.data`, возвращает заголовки ответа (нужно для пагинации).
- **`internal/cli`** — роутер `<resource> <verb>` (таблица `routes` в `cli.go`); `search` — special-case без verb-уровня. Глобальный `--json` извлекается до роутинга и передаётся хендлерам как `jsonOut`. `Deps{Client, Stdout, Stderr, Stdin, Now}` — потоки/время инъектируются (тесты кладут `bytes.Buffer`). Контракт `TalkClient`-интерфейса — compile-time проверка `var _ TalkClient = (*client.TalkClient)(nil)` (рассинхрон методов роняет сборку).
- **`internal/render`** — текстовые таблицы и `--json`; `SubstituteParams` (подстановка плейсхолдеров), `ParseSince`/`ParseRelativeAt` (относительное время `1h`/`2d`), `FormatTime`.
- **`internal/transport` / `internal/room` / `internal/exit`** — общие примитивы: HTTP/OCS-транспорт (`DoOCS`, конверт `ocs.data`, Basic-auth + OCS-заголовки, redirect-политика), WebDAV-транспорт `DoDAV` (HTTP-статус — вызывающему, `s:message` Sabre), `ResolveRoom` и exit-контракт `0/1/2/3` (value-тип `ExitError`: `errors.As` с value-target). Появились при рефакторинге под звонки — звонки удалены (2026-09-24), примитивы остались: `client` делегирует через alias.

## Неочевидные инварианты (нарушать опасно — проверяй тестами)

- **`messageParameters` имеет РАЗНЫЙ формат по эндпоинтам**: chat-API (`/api/v1/chat`) — **объект при непустых параметрах** `{actor,file,mention-*}`, пустые — **массив** `[]` (PHP-сериализация пустоты, spreed 24.0.4); непустой массив в chat-API не встречается; `/v4/room` `lastMessage` для `comment` — **массив** `[]`, для `system` — объект. Тип `client.MsgParams` с `UnmarshalJSON` принимает оба. **Фикстуры `testdata/` обязаны отражать реальный формат каждого эндпоинта** — самопальные объектные фикстуры однажды скрыли баг, который вскрылся только e2e на боевом.
- **Redact кредов**: пароль только в заголовке `Authorization` (никогда в URL — config отвергает userinfo); все ошибки проходят через `sanitizeErr` (чистит URL userinfo/query); `CheckRedirect` блокирует cross-host и **https→http даунгрейд**. Регресс-тест `TestRun_PasswordDoesNotLeak_CrossHostRedirect` (с `NEXTCLOUD_PASS=SECRET_MARKER`) — должен оставаться зелёным.
- **Exit-коды** (`internal/cli/exit.go`, спека §7): `0` успех (в т.ч. пустой результат поиска) · `1` общая ошибка (сеть/**401**/5xx) · `2` not found · `3` ambiguous. Маппинг: `exitFromClientErr` → `*client.OCSError{Code:404}` даёт `2`, остальное `1`. `ResolveRoom` (`room.go`) → `3` (>1 совпадение по `--name`) или `2` (0 совпадений). Константа для кода 1 — `ExitGeneric` (не `ExitError`: то имя занято типом).
- **Пагинация `GetChat`**: курсор следующей страницы — из **заголовка ответа `X-Chat-Last-Given`** (не из тела, не зависит от порядка new→old); стоп при пустом/неизменившемся заголовке; `304`/`204` = пусто/конец истории (трактовать как пустую страницу, без decode-ошибки). Серверу шлём `setReadMarker=0` (чтение не сбрасывает unread) и `limit=min(opts.Limit, 200)`.
- **Фильтры `chat show`**: `--from`/`--since` — клиентские (серверного фильтра по автору/времени в chat-API нет). `--last=0` означает «не задан» → потолок cap 200 при наличии `--from`/`--since`, иначе дефолт 20. System-сообщения скрыты по умолчанию (`--system` показывает).
- **`*client.OCSError{Code}`**: `Code` = OCS `meta.statusCode`; HTTP 404 (включая серверный `998` «Invalid query») нормализуется в `Code=404`.
- **`chat edit` / `EditMessage`** (PUT `/chat/{token}/{messageId}`, спека 2026-09-08): ответ сервера — **системное сообщение, где обновлённое лежит в `parent`**; id для вывода берём из `ocs.data.parent.id` (НЕ эхо аргумента) и guard `parent.id <= 0` обязателен — иначе format-drift даёт молчаливый `0` с exit 0 (регресс-тест `TestEditMessage_ResponseWithoutParent_FormatDrift`). Чтение тела (общий `readMessageBody`: stdin/`--file`, трим одного `\n`) — ДО `ResolveRoom`, пустое тело отсекается без сети. Распределение позиционных `<room> <messageId>` — как у `reactions get` (1 позиционный при `--name` = `messageId`). Ограничения правки (24 ч, свои/модератор, comment-only) — серверные, клиент не дублирует. Мутация проверена на живом API 2026-09-09 (`TestIntegration_EditMessage` PASS).
- **Треды** (спека-дельта 2026-09-29): id треда = id корневого сообщения — читать (`--thread`), отвечать (`--thread`) и ссылаться одним числом; Thread-запись создаётся ТОЛЬКО отправкой нового сообщения с непустым `threadTitle` (конвертировать существующее API не умеет); `replyTo` на сообщение треда кладёт ответ в тред (с цитатой) — сервер резолвит сам; выдача `chat?threadId=N` ВКЛЮЧАЕТ корень; общая история НЕ фильтрует ответы тредов (аннотации `⟲N`/`↩id` в `chat show` осмысленны; `↩` подавляется в `--thread`-режиме, условие `threadTitle != ""` = «Thread-запись загружена»); сервер без capability `threads` молча игнорирует `threadId` — клиент не проверяет (тонкий); `--reply-to`/`--thread`/`--thread-title` взаимоисключаемы (guard в cli до сети); send в несуществующий тред = HTTP 400 (`{"error":"reply-to"}`), НЕ 404 → exit `1`.
- **Вложения** (спека-дельта 2026-10-09, `chat send --attach`): классический механизм Talk — WebDAV PUT в папку вложений (`spreed.config.attachments.folder`, дефолт `/Talk`) + OCS-шаринг `shareType=10`; `talkMetaData` — JSON-СТРОКА (`caption`/`replyTo`/`threadId`/`threadTitle`/`silent`, пусто — `"{}"`); conversation subfolders Talk 24 отклонены. Ответ шаринга id сообщения НЕ содержит → поиск `GetChat{Limit: 50}` по нормализованному `referenceId` (`trim(substr(ref, 0, 64))`), system того же запроса (`thread_created`) пропускаются, из кандидатов — max id; промах — exit `0` + предупреждение (`{"id": null}`): файл уже отправлен, повтор дал бы дубликат. Для файлов сервер МОЛЧА игнорирует невалидные `replyTo`/`threadId` → pre-check до загрузки (`threads/{id}`; `{id}/context?limit=0` отдаёт СОСЕДА для несуществующего id — сверять id и `isReplyable`). Порядок `SendFile`: валидация → uid + настройки вложений → pre-check → имя + PUT (+MKCOL) → шаринг (+cleanup DELETE) → поиск id. PUT всегда с `If-None-Match: *` (существующее не перезаписывается; 412 → следующее имя ` (N)` по правилу веб-клиента), `Content-Length` без chunked, тело — `io.NopCloser` (Transport закрыл бы `*os.File`, повтор после 409/412 упал бы), пустой файл — `http.NoBody`. Логин ≠ uid: путь WebDAV — по `GET /cloud/user` → `id`. Классический путь папку вложений НЕ создаёт — MKCOL по 404/409 (живой сервер на PUT без папки отвечает 404, голый Sabre — 409), один раз; DAV-404 — ошибка WebDAV (exit `1`), не OCS 404. PUT — через отдельный upload-клиент без `Timeout` (срок — контекст: `NEXTCLOUD_TIMEOUT` + 1 с на 64 КиБ). Подпись необязательна; stdin — символьное устройство (терминал, `/dev/null`) → при `--attach` не читается; правило — на итоговом reader-е после fallback `nil → os.Stdin`. В cli `os.Stat` до `os.Open` (FIFO без писателя блокирует open). После любой ошибки шаринга — cleanup DELETE (неудача → путь файла в тексте ошибки).
