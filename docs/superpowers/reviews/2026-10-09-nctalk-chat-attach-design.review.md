## Minor

1. **M-1 (защитное)**: `internal/transport/dav.go:71-83`. Ветка `case contentLength == 0`
   молча отбрасывает непустой `body`. При `contentLength < 0` срабатывает `default`:
   `req.ContentLength = -1` даёт chunked transfer-encoding, вопреки инварианту «без chunked»
   (спека §3.4). Сейчас это недостижимо: `validateSendFile` гарантирует `Size >= 0`, клиенты
   передают `st.Size()`. Но контракт функции этого не требует.
   Сценарий сбоя: будущий вызов `DoDAV(..., body, -1)` (например, из `files ls/get/find`) —
   сервер получит пустое тело или обрыв за php-fpm.
   Предложение: guard `contentLength < 0` → ошибка; `contentLength == 0 && body != nil` —
   ошибка, либо строже задокументировать контракт.
2. **M-2 (гонка, теоретическая)**: `internal/cli/handlers_chat.go:613-620`. Порядок
   `os.Stat` → `os.Open` не закрывает подмену на FIFO полностью. Если между Stat и Open файл
   заменён на FIFO через символьную ссылку, `open(2)` заблокируется навсегда. Повторный `Stat`
   открытого fd (строка 625) защищает тип только ПОСЛЕ открытия, а не само открытие.
   Сценарий сбоя: скрипт с `ln -sf` попадает в окно в несколько микросекунд. Практический
   риск низкий: файл задаёт сам пользователь. Но комментарий обещает «закрывает подмену», а
   защита неполна.
   Предложение: открывать с `syscall.O_NONBLOCK` и снимать флаг после проверки, либо смягчить
   комментарий.
3. **M-3 (расхождение с веб-клиентом, крайний случай)**:
   `internal/client/files_helpers.go:58-72`.
   - Имя `..pdf` даёт `base = "."` и кандидата `. (2).pdf`: ведущая точка и пробел.
     Функционально это безопасно, `". (2).pdf"` — валидный сегмент, `path.Join` его не
     схлопывает. Но на сервере имя выглядит бракованным.
   - То же с `x (99999999999999999999).pdf`: `Atoi` переполняется, суффикс не распознаётся,
     кандидат — `x (999…9) (2).pdf`.

   Сценарий сбоя: только косметика в `/Talk`, перезаписи нет.
   Предложение: при `base == "."` или `base == ""` считать имя целиком основой.
4. **M-4 (эффективность и упрощение)**: `internal/client/files.go:295-296` и
   `internal/client/files_helpers.go:78-84`. `nameCandidate(f.Name, i)` на каждой итерации,
   до 1000 раз, заново гоняет два regex (`splitFileName`). Это дёшево, но разбор не зависит от
   `i`: можно один раз вычислить `(base, n, ext)` до цикла и собирать кандидата конкатенацией.
   Сценария сбоя нет, это чистое упрощение.

## Наблюдения (не дефекты, менять не предлагается)

1. **HEAD перед каждым PUT.** На отправку уходит минимум 2 запроса WebDAV. PUT с
   `If-None-Match: *` сам сигнализирует занятость имени ответом 412, поэтому в счастливом пути
   HEAD лишний. Но HEAD прямо предписан спекой §3.4 — это точка экономии round-trip на будущее,
   а не замечание к коду.
2. **Поиск id в окне 50 сообщений** устойчив: берётся максимальный id, system-сообщения
   пропускаются, нормализация побайтно как у сервера. Вытеснение из окна 50+ сообщениями за
   один round-trip осознанно задокументировано (§3.6). Exit 0 с предупреждением — правильная
   семантика: повтор дал бы дубликат.

## Проверено ревьюером и не найдено

1. Утечка пароля в ошибки DAV: `SanitizeErr` и регресс-тест с редиректом PUT.
2. Закрытие `*os.File` транспортом: `io.NopCloser` и тест на переиспользование тела.
3. Зацикливание пагинации при поиске id: потолок на 50, ровно один запрос.
4. Двойное экранирование пути: транспорт кодирует, клиент кладёт как есть.
5. Превращение DAV-404 в OCS 404: в тестах есть регресс-проверка «не `*OCSError`».

## Верификация (superpowers:receiving-code-review, 2026-10-10)

Итог: **2 валидных исправлены, 2 ложных отброшены**; плюс одна находка вне ревью исправлена.

1. **M-1 — valid, исправлено.** `DoDAV` с `contentLength < 0` возвращает ошибку до сети (тест
   `TestDoDAV_NegativeContentLength`, red: при -1 и -5 тело уходило chunked, ответ 201). Вторая
   часть предложения («`contentLength == 0 && body != nil` → ошибка») не принята: она ломает

   Ревьюер с объёмом фикса согласился.
2. **M-2 — valid, исправлен комментарий.** Комментарий `chatSendAttach` и спека §2.3/§6 больше

   `O_NONBLOCK` отклонён: снятие флага требует unix-only кода, а оставленный флаг на darwin
   кладёт обычный файл в kqueue. Окно — микросекунды, путь задаёт сам пользователь, исход —

   Ревьюер замечание снял.
4. **M-4 — false-positive.** Эффекта нет: 1000 кандидатов — около 0,45 мс, а каждая итерация и
   так делает HEAD по сети. Вынос разбора из цикла продублировал бы логику `nameCandidate`.

   отвечал 201, а net/http возвращал клиенту `ContentLength=N with Body length M`. Итог —

   `io.LimitReader` на N байт, снимок на момент `Stat` (тест
   `TestDoDAV_BodyLongerThanContentLength`, red 10/10 → green 10/10; укоротившийся файл —
