# nctalk-audio-calls — проектирование аудио-звонков WebRTC для nctalk

## Контекст
Пользователь спросил, насколько сложно встроить в `nctalk` (тонкий CLI над Nextcloud
Talk на Go) возможность **подключаться к звонку и транслировать звук (и, возможно,
видео)**. Разобрались через `superpowers:brainstorming` — цель: реальное аудио в
звонках Talk (слушать + говорить) из терминала/процесса, как отдельный изолированный
модуль к существующему `nctalk`.

только по явной просьбе).

## Инсайты и решения
- **Звонок Talk = 2 независимых слоя:** (1) Call API `POST/GET/PUT/DELETE
  /ocs/v2.php/apps/spreed/api/v4/call/{token}` — чистый OCS-HTTP, фиксирует
  присутствие + flags потоков, медиа НЕ передаёт (на этом уже стоит `nctalk`);
  (2) signaling + WebRTC — реальный медиа (SDP/ICE, DTLS-SRTP), этого слоя в проекте нет.
- **Заявленные требования пользователя:** реальное аудио; только macOS; только малые
  звонки P2P (≤7, internal OCS-signaling polling); только аудио (видео нет); два
  режима как **отдельные модули** (человек-TUI + агент-pipe); **минимально инвазивно**;
  **легко выпилить** если монструозно.
- **Архитектура:** один `go.mod` (не отдельные модули — иначе Go `internal/` запретит
  импорт `internal/client`); изоляция через отдельные `cmd/`-бинарники; линкер не
  тащит pion в базовый `nctalk`.
- **Структура:** `internal/call/{signaling,peer,media,agent,interactive}` + `cmd/nctalk-call`
  (pipe/агент) + `cmd/nctalk-talk` (TUI/человек). Общее ядро делят оба режима.
- **Граница удаления:** `rm -rf internal/call cmd/nctalk-call cmd/nctalk-talk && go mod
  tidy`. Инвариант: `internal/{client,config,redact}` получают НОЛЬ новых зависимостей и
  строк про WebRTC → откат тривиален и проверяем.
- **CGO_ENABLED=0 сохраняется глобально:** codec + audio-IO через `ffmpeg`-subprocess
  (вариант a), pion работает через Sample API без ручной RTP-упаковки.
- **WebRTC:** `github.com/pion/webrtc/v4`; P2P-mesh — своя `PeerConnection` на каждого
  участника.
- **Два ключевых риска:** (1) signaling-протокол Talk недокументирован — формат
  сообщений `usersInRoom`/`offer`/`answer`/`candidate` реверсится из JS-кода `spreed`,
  проверяется spike'ом; (2) Opus-кодека нет в pion — решается ffmpeg-subprocess,
  fallback libopus-CGO если монструозно, локализовано в `call/media`.

## Отвергнутые подходы
- **Подход 2 (pion + CGO CoreAudio/portaudio):** ломает `CGO_ENABLED=0` — фундаментальный
  инвариант.
- **Подход 3 (headless Chrome / gstreamer-webrtc):** ломает «тонкий CLI», огромная
  зависимость, не выпилится чисто (хоть и снимает risk#1 через готовый signaling).
- **libopus через CGO как основной codec:** ломает CGO=0; оставлен только как fallback.
- **Видео / HPB-SFU / Windows-Linux / нативная CoreAudio / изменения в существующем
  nctalk** — все в Out of scope.

## Открытые вопросы
- **Ревью спеки** пользователем — ждём, могут быть правки.
- **Коммит:** пользователь не давал явного добра на коммит; в сессии git branch
  отображается `HEAD` (возможно detached) — перед коммитом проверить `git status` и
  согласовать ветку (main vs feature-branch).
- **HPB на боевом сервере:** не проверено, есть ли (пользователь выбрал P2P, так что
  не блокирует, но spike может выявить).
